# Тренажёр слепой печати — спецификация

Nov 4, 2026 · @Andrii

## Видение и принципы

Личный офлайн-тренажёр слепой печати для Windows, который учится вместе с пользователем: ML-модель находит слабые клавиши, переходы и символы и сама подбирает тренировку. Публичный репозиторий под MIT, но в первую очередь — инструмент для себя.

- **Офлайн прежде всего.** Всё основное работает без интернета. Сеть нужна только для музыки, YouTube и синхронизации.
- **Данные — источник истины.** Каждое нажатие пишется в журнал. Статистика, уровни, ачивки и модели вычисляются из него.
- **Честные метрики.** Прогресс измеряется на реальном навыке (слабые переходы), а не на скорости в лёгких текстах.
- **Всё настраивается.** Каждая политика и функция переключается, по умолчанию включено всё.
- **Интересно, а не скучно.** Геймификация поверх реальных навыков, а не ради галочек.
- **Оригинальный код.** Ничего не копируем из чужих репозиториев.
- **Решения задокументированы.** Каждое архитектурное решение записано (ADR) с причинами и компромиссами.

## Стек

Tauri 2 с ядром на Rust и интерфейсом на Vue 3: лёгкий офлайн-бинарник, а UI на знакомом стеке.

| Слой | Технология | Зачем |
| --- | --- | --- |
| Оболочка | Tauri 2 | Маленький бинарник, трей, автозапуск, системные уведомления |
| Интерфейс | Vue 3 + TypeScript + Vite, Pinia | Знакомый стек, реактивный UI для экрана набора и дашборда |
| Ядро | Rust | Журнал, проекции, мозг, генератор текста, синхронизация, фоновые задачи |
| Хранилище | Журналы JSONL + SQLite | Журнал — источник истины, SQLite — быстрые производные таблицы |
| Графики | uPlot (ADR-0009) | Тренды. Тепловая карта, пальцы и матрица переходов сделаны на HTML и токенах |
| Исследования | Python: Jupyter, pandas, LightGBM | Эксперименты с моделями на экспортированных журналах |
| Тесты | cargo test, Vitest | Ядро и мозг покрыты тестами, UI — компонентами |

Два технических правила для экрана набора:

- **Физическая клавиша, а не символ.** Хранить и `event.code` (физическая клавиша), и сам символ. Тогда палец и позиция на клавиатуре не зависят от раскладки, а RU/UA добавляются без переделки статистики.
- **Точное время.** Отметки времени берутся из `event.timeStamp` (те же часы, что у `performance.now()`, но это момент получения ввода, поэтому занятость UI не искажает интервалы) и уходят в ядро пачками, чтобы не было задержек на мосту UI ↔ Rust.

## Архитектура

Всё строится вокруг журнала событий, куда записи только добавляются: остальные части читают его и ничего в нём не меняют.

1. **Экран набора (UI)** ловит нажатия, считает время и отправляет пачки событий в ядро.
2. **Журнал** дописывает события в файлы JSONL, по папке на устройство.
3. **Проектор** читает журнал и обновляет производные таблицы в SQLite. Базу можно удалить и пересобрать из журналов в любой момент.
4. **Мозг** читает статистику, обучает модель ученика и выбирает следующую тренировку.
5. **Генератор текста** собирает упражнение под цели мозга: слова, псевдослова, тексты, код.
6. **Движок правил** считает XP, уровни, цели, задания, ивенты и ачивки по данным из SQLite.
7. **Советчик** формирует подсказки по метрикам.
8. **Фоновые службы:** трей, напоминания, синхронизация, интеграции (LRCLIB, медиа-контролы Windows, yt-dlp).

## Модель данных

Журнал хранит сырые события, SQLite — только то, что из них вычисляется.

**Журнал:** `journal/<device-id>/<YYYY-MM-DD>.jsonl`, одна строка — одно событие. Дата в имени файла — по UTC, локальное время со смещением записано в `session_started`. В каждом событии есть версия схемы, а в событиях сессии ещё id сессии и порядковый номер `seq`: читатель отбрасывает повторы по этой паре. Подробности в ADR-0003.

| Событие | Ключевые поля |
| --- | --- |
| `session_started` | id сессии, режим, раскладка, источник текста, снимок настроек, версия приложения |
| `keystroke` | время от первого нажатия (мс, дробное), вид (`char`, `backspace`, `modifier`), `code`, введённый символ, ожидаемый символ, верно ли, позиция в тексте, удерживаемые модификаторы, `ignored` для нажатий, которые не изменили текст (`layout` — другая раскладка, `policy` — запрет Backspace) |
| `session_paused`, `session_resumed` | время от первого нажатия; активная длительность считается без пауз |
| `session_ended` | причина (завершена, прервана), итоговая длительность без пауз |
| `settings_changed` | что изменилось, старое и новое значение |
| `reward_granted` | ачивка, задание или уровень и момент получения |

Запись `reward_granted` нужна, чтобы награды не выдавались повторно, если правила потом изменятся.

**Производные таблицы SQLite** (файл `derived.sqlite` рядом с настройками, пересобирается из журнала, см. ADR-0008):

- `sessions` — итоги сессий: WPM, CPM, точность, ровность ритма.
- `key_stats`, `bigram_stats` — нажатия, время, разброс времени и ошибки по каждой клавише и переходу за день. `trigram_stats` появится на этапе 8: до признаков бустинга его никто не читает.
- `daily_stats` — представление над `sessions`: агрегаты по дням для трендов и стриков. Представление, а не таблица, потому что вторая копия чисел могла бы разойтись с первой.
- `last_setups` — представление над `sessions`: последняя запущенная настройка каждого режима и устройство, на котором она запущена (ADR-0007).
- `projected_files`, `session_state` — служебные: докуда прочитан каждый файл и состояние незавершённых сессий.
- `model_state` — модель ученика по каждой букве и паре букв: суммы с забыванием на дату последней практики, стабильность, освоена ли (ADR-0010). Считается заново из `key_stats` и `bigram_stats` после каждого прохода проектора. Параметры бандита добавятся на этапе 8.
- `session_targets` — цели каждой адаптивной сессии: оценка мозга на старте и что сессия намерила по ним с теми же определениями, что `key_stats` и `bigram_stats` (ADR-0010). Из неё итоги и колонка «Target gain» показывают прирост. Награда этапа 8 считается из этой же таблицы.
- `session_keys` — клавиши каждого стартового теста отдельно, с теми же определениями, что `key_stats`. Из неё экран результата рисует рельеф только этой минуты (ADR-0012). Другие режимы сюда ничего не пишут.
- `progress` — XP, уровень, цели, задания, ачивки, с этапа 4.

Определения нажатий, ошибок, переходов и дат записаны в ADR-0008. Миграций нет: база другой версии удаляется и пересобирается.

## Адаптивный мозг

Мозг состоит из двух моделей: модель ученика знает, что ты умеешь, модель решений выбирает, что тренировать. Обе маленькие и дообучаются на ПК в фоне.

**Признаки перехода X→Y:** предыдущий и следующий символ, пара пальцев, та же рука или тот же палец, смена ряда, нужен ли Shift, позиция в слове, минуты от начала сессии (усталость), время с последней тренировки этого перехода, режим.

**Модель ученика** предсказывает для каждого перехода время (мс) и вероятность ошибки.

- v1: байесовские оценки по каждой букве и паре букв с забыванием по календарным дням (ADR-0010).
- v2: градиентный бустинг на решающих деревьях, переобучается в фоне после сессий. Через признаки он обобщает на редкие и новые переходы: незнакомая биграмма на тех же пальцах получает разумный прогноз.
- Интервальное повторение: у каждой n-граммы есть «стабильность», и давно не тренированные переходы планируются на повторение до того, как забудутся.

**Модель решений** — контекстный бандит (Thompson sampling). Выбирает «рецепт» упражнения: какие переходы в фокусе, доля нового и повторения, длина, сложность.

**Награда** — измеренный прирост на целевых переходах в следующих сессиях, а не WPM текущей. Иначе бандит научится давать лёгкие тексты.

**Холодный старт.** Пока данных мало, работает эвристика: буквы открываются по частоте, в фокусе самая слабая клавиша. После порога данных (параметр, значение подбирается экспериментом) управление переходит к ML. Правила эвристики, порог освоения и открытие букв записаны в ADR-0010.

**Проверка, что ML лучше.** Сессии чередуют эвристику и ML (A/B), дашборд показывает, где прирост выше. Каждое изменение модели — отдельный зарегистрированный эксперимент.

**Метрики:** WPM, CPM, точность, ровность ритма (разброс интервалов), время восстановления после сложного символа, типы ошибок (замена, перестановка, пропуск), кривая усталости.

**Генератор текста** получает цели от мозга и подбирает: частые слова, содержащие целевые n-граммы; псевдослова из цепи Маркова, обученной на словаре; реальные тексты с нужным покрытием n-грамм; фрагменты кода. На этапе 3 есть первые два источника, а сессия рассчитана примерно на 3 минуты (ADR-0011).

**Объяснимость.** Важность признаков бустинга идёт в советы и в панель «Почему эта тренировка».

## Режимы набора

Все режимы пишут в один журнал, так что любая практика кормит мозг и статистику.

| Режим | Что делает | Этап |
| --- | --- | --- |
| Адаптивный | Упражнения, которые собирает мозг | 3 |
| Стартовый тест | Одна минута лёгких отрывков, рисует первую карту и открывает буквы, которые уже в пороге | 3 |
| Слова | Частые слова, по времени или по количеству | 1 |
| Тексты | Цитаты, свои тексты, импорт TXT/EPUB | 1 |
| Дзен | Бесконечный набор без метрик на экране, Enter начинает новую строку | 1 |
| Призрак | Гонка со своим прошлым результатом на том же тексте | 4 |
| Испытания | Особые условия: без ошибок, внезапная смерть, слепой режим | 4 |
| Код | Фрагменты на разных языках и код из своих репозиториев | 5 |
| Символы и цифры | Тренировка спецсимволов, цифр и Shift-сочетаний | 5 |
| Ритм | Метроном, тренировка ровного темпа | позже |
| Музыка | Синхронизированный текст песни (LRCLIB) | 9 |
| Видео | Субтитры: пауза до набора строки или непрерывное воспроизведение | 10 |

**Запомненная настройка.** Главная предлагает повторить последнюю сессию одним действием. Настройка каждого режима выводится из его последнего `session_started`, отдельного события для неё нет (ADR-0007). Значит, запоминается то, что запускалось: изменение без запуска забывается.

| Источник | Что повторяется | Когда повторить нельзя |
| --- | --- | --- |
| Слова | Длина и набор слов, текст новый | Всегда можно |
| Отрывки | Сложность, отрывок новый | Всегда можно |
| Файл | Тот же файл с места, где остановились | Файл удалён, лежит на другом устройстве или дочитан |
| Вставка | Ничего: текст намеренно не хранится в журнале | Никогда нельзя |
| Дзен | Настроек нет | Всегда можно |

Если повторить нельзя, главная не запускает сессию сразу, а ведёт на настройку этого режима; остальные режимы по-прежнему запускаются одним действием. В журнале у файла только `id`, а название живёт в локальной библиотеке, поэтому удалённый файл или файл с другого устройства главная назвать не может. Вид этого состояния — в макете `home-now` и в `design/README.md`.

**Режим кода** решает конкретную проблему: после `{` и других символов теряется ритм и растут ошибки.

- Отслеживается время восстановления: насколько медленнее и с какими ошибками идут 3–5 символов после сложного символа.
- Shift-сочетания учитываются отдельно (`{` = Shift + `[`), чтобы понять, сбивает символ или Shift.
- Настройки: автоотступ или ручной ввод отступов, табы или пробелы, автозакрытие скобок вкл/выкл.
- Источники: встроенные фрагменты на нескольких языках и локальные папки с собственным кодом.

## Контент: слова и тексты

Слова и тексты поставляются вместе с приложением и собираются воспроизводимым Python-скриптом в `tools/content/`. Код остаётся под MIT, у данных в `content/` — свои лицензии, записанные в `content/LICENSES.md`.

| Что | Источник | Лицензия | Как используется |
| --- | --- | --- | --- |
| Частотный словарь EN | [wordfreq 3.1.1](https://pypi.org/project/wordfreq/3.1.1/) | Данные CC BY-SA 4.0 | Топ 10–20 тыс. слов с частотой; режим «Слова», генератор, обучение цепи Маркова |
| Запасной словарь EN | [top-english-wordlists](https://github.com/david47k/top-english-wordlists) (Google Ngrams) | CC BY 3.0 | Если проще нужна лицензия только с указанием авторства |
| Тексты и цитаты | Книги общественного достояния с Project Gutenberg | Общественное достояние, после удаления всех упоминаний Project Gutenberg ([пояснение](https://lists.debian.org/debian-devel/2025/03/msg00229.html)) | Нарезка на отрывки по 150–400 символов с оценкой сложности |
| Псевдослова | Генерируются цепью Маркова из словаря | Производные от словаря | Ранние этапы, когда открыты не все буквы |
| Фрагменты кода | Пишутся с нуля для проекта | MIT | Режим кода на нескольких языках |
| Свои тексты и код | Импорт пользователя (TXT, EPUB, папки) | Не попадает в репозиторий | Только локальный кэш |

Правила пайплайна:

1. Скачать источник, сохранить URL, дату и контрольную сумму. Сырые файлы не коммитятся.
2. Очистить: только буквы раскладки, фильтр ненормативной лексики, нормализация регистра и пунктуации.
3. Для отрывков посчитать признаки сложности: средняя длина слова, доля редких слов, плотность пунктуации, цифры, заглавные.
4. Сохранить `content/en/words.json` (слово, частота, ранг) и `content/en/passages.jsonl` (текст, источник, лицензия, сложность, покрытие n-грамм).
5. Дописать запись в `content/LICENSES.md`.

Импорт файла показывает бегущую полосу, которая появляется с небольшой задержкой, без процентов и без отмены; файлы импортируются по очереди. Причина в замере на release-сборке: EPUB на 20 млн символов занял 124 мс, TXT на 10 МБ — 208 мс, TXT на предельные 128 МБ — 2,4 с с паузой между кадрами до 123 мс. Тексты в замере синтетические и машина одна, поэтому к вопросу вернёмся, если настоящая книга окажется медленной.

Список google-10000-english, популярный в тренажёрах, не используем: [его лицензия](https://awesome.ecosyste.ms/projects/github.com%2Ffirst20hours%2Fgoogle-10000-english) неочевидна. Для RU и UA источник выбирается на этапе 11: оба частотных проекта многоязычные, покрытие нужно проверить.

## Прогресс и геймификация

Награды привязаны к реальному навыку: XP даётся за качество практики, а не просто за время.

**Движок правил.** Ачивки, задания, ивенты и испытания описываются в файлах `content/*.toml`: id, название, описание, условие, уровень сложности, флаг «скрытая», награда. Новая ачивка = новая запись, без изменения кода.

- **Уровни и XP.** XP = время практики × коэффициент точности + бонус за прирост на слабых переходах.
- **Цели дня и недели.** Ставит пользователь или предлагает мозг: минуты, сессии, точность, конкретный переход.
- **Задания.** Ежедневные и недельные, персональные от мозга, например «доведи переход `{` → Enter до целевого времени».
- **Ивенты.** Временные темы с датами в файлах контента (например, неделя символов). Работают офлайн по локальной дате.
- **Испытания.** Без единой ошибки, внезапная смерть, слепой режим (набранный текст скрывается), лестница скорости.
- **Достижения.** Уровни сложности от бронзы до платины + скрытые, которые раскрываются только после получения.
- **Стрики** с «заморозкой» дня. Отключаются в настройках.

**Дашборд:**

- Обзор: уровень, стрик, цели, последние сессии. На этапе 2 здесь рельеф на главной, две самые слабые клавиши и последние сессии; уровень, стрик и цели появятся на этапе 4.
- Тепловая карта клавиатуры по клавишам и пальцам.
- Матрица биграмм: скорость и ошибки по переходам.
- Тренды WPM, точности, ровности ритма.
- Рекорды и личные лучшие результаты. На этапе 2: лучшие WPM и точность среди завершённых сессий минимум из 100 верных символов, без Дзена.
- Панель мозга: что сейчас в фокусе, почему, и насколько ML лучше эвристики. Появится с этапа 3.

Шкалы, пороги «мало данных» и рекорды определены в ADR-0009: скорость на карте считается от личного медианного времени клавиши, ошибки — в абсолютных процентах. Типы ошибок и кривая усталости в макете есть, но на этапе 2 их нет: для них пока не считаются данные.

## Напоминания и советы

Приложение живёт в трее, поэтому напоминает о тренировке даже когда окно закрыто.

**Напоминания:**

- Автозапуск вместе с Windows (переключается).
- Напоминания по расписанию, например в 12:00, через системные уведомления.
- Умный режим: предлагает время по реальным привычкам.
- Тихие часы. Клик по уведомлению сразу открывает короткую сессию. Кнопки действий в плагине уведомлений Tauri заявлены только для мобильных платформ, поэтому на Windows уведомление — это заголовок и текст. Обработку клика на десктопе проверить на этапе 6; запасной вариант — маленькое собственное окно.

**Советы** строятся офлайн по правилам поверх метрик. Каждый совет показывает данные, на основе которых он появился.

- Медленный палец или рука относительно остальных.
- Переходы одним пальцем, которые тормозят.
- Долгое восстановление после символов.
- Усталость: точность падает после N минут — предложить перерыв.
- Генерация советов через LLM — позже, опционально и только онлайн.

## Синхронизация

Синхронизируются только журналы: каждое устройство пишет свои файлы, поэтому конфликтов нет, а слияние — простое объединение.

- **Папка (первый вариант).** Приложение пишет журналы в выбранную папку: Google Drive для компьютера, OneDrive, Dropbox. Интеграция с Google API не нужна.
- **Git (второй вариант).** Приложение коммитит журналы в приватный репозиторий и делает push/pull через git.
- **SQLite никогда не синхронизируется.** Живая база в облачной папке может повредиться, поэтому она всегда локальная и пересобирается из журналов.
- **Настройки:** выигрывает последняя запись по времени изменения.
- **Экспорт и импорт** всех данных одним ZIP-архивом.

## Первый запуск

Каждый шаг появляется вместе с тем, что он настраивает, поэтому онбординг растёт от этапа к этапу.

| Шаг | Когда появляется | Что делает |
| --- | --- | --- |
| Выбор темы | При переносе макетов | Светлая, тёмная или как в системе; заранее выбрано «как в системе» |
| Стартовый тест и экран результата | Этап 3 | Можно пропустить: у мозга есть эвристика холодного старта |
| Выбор раскладки | Этап 11 | До этого раскладка одна и выбирать нечего |

Макеты в `design/`: `onboarding-theme` — выбор темы, `onboarding-test` и `onboarding-result` — этап 3, `onboarding-layout` — этап 11.

- Шаг показывается один раз. Если закрыть окно, не сделав выбора, он появится при следующем запуске, а до выбора действует значение по умолчанию.
- Прохождение отмечается отдельным признаком в настройках через `settings_changed`: выбор значения, которое уже стоит, события не пишет, поэтому по самой теме первый запуск не определить. У темы это `theme_chosen`, у теста `test_done`: тест после пропуска не оставляет сессии, и без признака он появлялся бы снова.
- Стартовый тест (ADR-0012): одна минута лёгких отрывков, подобранных так, чтобы покрыть побольше букв. «Skip the test» ведёт на главную, а напечатанное до этого остаётся в журнале, как у любой сессии. Пройти тест снова можно с главной, пока сессий нет («Take the starting test»), и с экрана Brain.
- Если в журнале уже есть сессии, шаги не показываются.

## Лицензия и правила разработки

Проект под MIT, весь код оригинальный. Идеи и функции других тренажёров использовать можно, их код — нельзя: keybr выпущен под AGPL-3.0, Monkeytype под GPL-3.0, и их код несовместим с MIT.

- Код из чужих репозиториев не копируется и не пересказывается построчно.
- Списки слов и тексты — только из источников со свободной лицензией или общественного достояния. Источник и лицензия каждого файла записываются в `content/LICENSES.md`.
- Тексты песен, субтитры и видео никогда не попадают в репозиторий: они кэшируются только локально.
- Чужие торговые марки не используются в названии.
- Каждое архитектурное решение — ADR в `docs/adr/`: контекст, варианты, выбор, последствия.
- Работа маленькими шагами, каждый этап заканчивается рабочей сборкой.
- Ядро, проектор, генератор и мозг покрыты тестами.
- Коммиты по Conventional Commits.

Правила для агента лежат в `CLAUDE.md` в корне репозитория.

## Roadmap

Четырнадцать этапов от каркаса до звуков. Каждый этап — рабочая версия, которой уже можно пользоваться.

0. **Каркас.** Tauri + Vue, структура репозитория, CI, первые ADR.
1. **Ядро набора.** Экран набора, журнал, режимы «Слова», «Тексты», «Дзен», итоги сессии. Только EN.
2. **Проектор и дашборд v1.** SQLite, пересборка из журнала, перенос макетов, рельеф на главной, экран статистики: тепловая карта, пальцы, матрица переходов, тренды, рекорды.
3. **Мозг v1.** Эвристика холодного старта, байесовская модель ученика, генератор текста, адаптивный режим, стартовый тест.
4. **Геймификация.** XP и уровни, цели, задания, ачивки, испытания, призрак.
5. **Режим кода.** Символы, Shift-сочетания, время восстановления, код из своих папок.
6. **Трей, напоминания, советы.**
7. **Синхронизация.** Сначала папка, затем Git; экспорт и импорт.
8. **Мозг v2.** Градиентный бустинг, контекстный бандит, A/B-сравнение с эвристикой, `trigram_stats`.
9. **Музыка.** Медиа-контролы Windows + LRCLIB.
10. **Видео.** Локальные файлы + .srt, затем YouTube; оба режима воспроизведения.
11. **Раскладки RU и UA.** Шаг выбора раскладки при первом запуске.
12. **Экранная клавиатура во время набора.** Подсказка пальца и все три раскладки. Тепловая карта на экране статистики к ней не относится и появляется на этапе 2.
13. **Звуки.**

Клавиатура и звуки есть в таблице политик, но до этапов 12 и 13 их в приложении нет. Пока клавиатуры нет, экран набора использует вариант макета без неё, а награды этапа 4 показываются в той же полосе, что будет у клавиатуры: у нижнего края окна, в месте, зарезервированном токеном `--reward-band`. Поверх текста они не появляются.
