# Design

Design system and static mockups for the direction **Relief**, chosen in the design session.
The skill map is the idea: weak keys are hills on a contour map under the keyboard, and training
flattens them. The interface around it stays quiet, on paper-like surfaces with one warm accent.

Open `screens/index.html` in a browser. It works from the file system, no server needed. Fonts
load from Google Fonts in the mockups, so without a network the fallback faces show.

| Path                        | What it is                                                                   |
| --------------------------- | ---------------------------------------------------------------------------- |
| `screens/`                  | All mockups, `index.html` is the gallery, `components.html` the state matrix |
| `tokens.css`, `tokens.json` | Colours, fonts, spacing, radii and motion for both themes                    |
| `directions/`               | The three directions that were compared, kept for reference                  |
| `_build/`                   | Generators for the tokens and the screens                                    |
| `icon.svg`                  | Source of the app icon, generated by `_build/icon.mjs`                       |

Regenerate the tokens and the screens with `node design/_build/build.mjs`. It also checks 58
contrast pairs and prints any failure. `screens/assets/screens.css` and `screens/assets/review.js`
are written by hand.

The app icon is the next key, lit as on the typing screen, on a relief. To change it, edit
`_build/icon.mjs`, run it, and generate the sizes with `npx tauri icon design/icon.svg -o <temp folder>`.
Copy only the five files listed in `src-tauri/tauri.conf.json` and `icon.png` into `src-tauri/icons/`:
the command also creates Android, iOS and Windows Store sizes, which this project does not use.

The app imports `tokens.css` directly. `src/styles/relief.css` is a copy of the parts of
`screens/assets/screens.css` it uses so far, and `src/styles/app.css` holds what the mockups do not
draw, such as the session setup on the home screen.

## Principles

1. **The text comes first.** The typing screen has no navigation. The current character, errors and
   the next key are readable at a glance, everything else is quiet.
2. **State is never colour alone.** Each character state differs in shape as well as colour, so the
   screen survives colour blindness and a greyscale display. See "Typed text" below.
3. **The accent means "now".** It marks the primary action, the current selection and the current
   character. One filled primary button per screen.
4. **Rewards stay out of the way.** They appear in the keyboard band, beside the keyboard, never over
   the text. They take no focus, shift no layout and fade on their own.
5. **Data explains itself.** Focus, tips and the brain panel state the figure behind them. An
   inconclusive A/B result is shown as inconclusive.
6. **Every policy has a switch.** Clean mode removes XP, levels, quests, events and achievements from
   every screen and leaves a complete app.
7. **Failure is calm and offline.** Error states say what is safe and what to do. The journal is
   always the way back.

## Using the mockups

Each screen has a Mockup control at the bottom right: theme, data state, clean mode, colour vision
simulation, and on typing screens the keyboard mode and reward demos. The same options work as URL
parameters: `?theme=dark`, `?data=loading|empty|error`, `?gam=off`, `?kbd=error|off`, `?vision=...`.

Typing screens accept real keystrokes: errors, Backspace, Enter with auto-indent on the code screen,
Esc to pause. This is a demo in `review.js`, not a design for the input path. All figures are samples,
and lyrics, subtitles and videos are original placeholders.

Screens are checked at 1366×768 and 1920×1080. Above 1366 the content is capped and centred, and the
typing text and keys grow.

## Tokens

Components use role names and never raw values, so a theme is only a set of role values. The source
is OKLCH, with sRGB hex alongside in `tokens.json`.

| Group            | Names                                                                                                         |
| ---------------- | ------------------------------------------------------------------------------------------------------------- |
| Surfaces and ink | `--color-paper`, `-paper-2`, `-paper-3`, `-ink`, `-ink-2`, `-muted`, `-rule`, `-rule-2`, `-field-edge`        |
| Meaning          | `--color-accent`, `-accent-soft`, `-signal`, `-focus`, `-target`, `-target-soft`                              |
| Typed text       | `--color-upcoming`, `-done`, `-caret-bg`, `-error-bg`, `-error-ink`, `-error-mark`                            |
| Data             | `--color-heat-0` to `-5`, `--color-chart-1`, `-chart-2`, `--color-contour`                                    |
| Type             | `--font-ui`, `-display`, `-typing`, `-code`; `--text-xs` to `-4xl`; `--weight-regular`, `-medium`, `-display` |
| Space and shape  | `--space-3xs` to `-3xl`; `--radius-glyph`, `-ui`, `-key`, `-pill`; `--control-sm`, `-md`, `-hit`              |
| Motion           | `--dur-micro`, `-short`, `-long`, `-ripple`, `-reward`; `--ease-out`, `-settle`                               |

Fonts are Golos Text and JetBrains Mono, both under the SIL Open Font License, both with Cyrillic
including Ukrainian. The app has to bundle them as woff2 to stay offline.

Chart colours pass the dataviz palette validator in both themes. Heat is one hue from light to dark,
and a number stays on each key, so the map never relies on colour alone.

## Components and states

`screens/components.html` draws every component below in the states normal, hover, focus, error and
disabled, in both themes.

| Group      | Components                                                                   |
| ---------- | ---------------------------------------------------------------------------- |
| Controls   | Button (primary, secondary, quiet), input, select, switch, segmented control |
| Navigation | Top bar item, tab, link                                                      |
| Product    | Key, quest row, achievement row, session row, meter, heat cell, reward       |

Rules shared by all states:

- **Hover** changes the surface. A switch gets a soft ring instead.
- **Focus** is a 2px ring from `--color-focus`, shown instantly on `:focus-visible`.
- **Error** uses `--color-signal`, a heavier edge and a "!" glyph with a message, not red.
- **Disabled** lowers contrast and removes hover. Explanatory text stays readable.

### Typed text

| State                     | Shape                                                            | Why it reads without colour           |
| ------------------------- | ---------------------------------------------------------------- | ------------------------------------- |
| Upcoming                  | Muted ink                                                        | Lighter than done text                |
| Target                    | Thick underline under the transition                             | Line under the letters                |
| Current                   | Filled block in the accent                                       | Filled block                          |
| Done                      | Full ink                                                         | Darker than upcoming text             |
| Error                     | Inverted block, heavy lower mark, typed character in a tag above | Inverted, with the wrong letter shown |
| Fixed                     | Dotted underline                                                 | Stays visible after the correction    |
| Skipped, continuous video | Struck through                                                   | Line through the letters              |

### On-screen keyboard

There is one component, `keyboard()` in `_build/lib.mjs`, with the finger hint `hand()` beside it. It
takes these variants:

- **Typing:** next key filled in the accent, target keys underlined, the finger named in words.
- **Locked:** keys that have not opened yet.
- **Heat:** the statistics screen, one attribute `data-h` per key, switched by metric and by view.
- **Ghost:** quiet keys over the relief on the home and onboarding screens.
- **Key feedback:** pressed `is-down`, wrong press `is-wrong`.

The policy has three modes: on, only on error, and off. The band keeps its space in "only on error",
so the text does not jump. When the keyboard is off, the text takes the space and rewards move to the
bottom edge of the window.

### Data states

Every region that reads data has four states: full, loading (skeleton), empty (what to do next) and
error (what is safe, and a way back). The markup comes from `region()` in `_build/lib.mjs`.

### Rewards

| Reward     | Position                             | Motion                                              |
| ---------- | ------------------------------------ | --------------------------------------------------- |
| XP         | Left of the keyboard                 | Fades in and out, 2.6 s                             |
| Quest done | Right of the keyboard                | Same                                                |
| Level up   | Right of the keyboard, in the accent | Same, plus a contour ripple through the band, 0.9 s |

With `prefers-reduced-motion` the rewards appear without movement and the ripple does not run. If
several arrive together, they stack in their column.

## Tray and notification

`screens/tray.html` shows content only. In the app both are native Windows surfaces, so Relief styling
does not reach them:

- The Tauri 2 tray menu supports text, check items, separators, disabled items and text updates.
- The Tauri notification plugin documents action buttons for mobile only, so the Windows reminder is
  a title and a body.
- Whether the plugin reports a click on desktop is unconfirmed. Check this at stage 6, because SPEC
  wants a click to open a short session. A small custom webview window is the fallback.
