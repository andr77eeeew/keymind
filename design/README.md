# Design

Design system and static mockups for the direction **Relief**, chosen in the design session.
The skill map is the idea: weak keys are hills on a contour map under the keyboard, and training
flattens them. The interface around it stays quiet, on paper-like surfaces with one warm accent.

Open `screens/index.html` in a browser. It works from the file system, no server and no network
needed: the fonts are in `screens/assets/fonts/`, the same files the app bundles.

| Path                        | What it is                                                                   |
| --------------------------- | ---------------------------------------------------------------------------- |
| `screens/`                  | All mockups, `index.html` is the gallery, `components.html` the state matrix |
| `tokens.css`, `tokens.json` | Colours, fonts, spacing, radii and motion for both themes                    |
| `directions/`               | The three directions that were compared, kept for reference                  |
| `_build/`                   | Generators for the tokens and the screens                                    |
| `icon.svg`                  | Source of the app icon, generated by `_build/icon.mjs`                       |

Regenerate the tokens and the screens with `node design/_build/build.mjs`. It also checks 62
contrast pairs and prints any failure. `screens/assets/screens.css` and `screens/assets/review.js`
are written by hand.

The app icon is the next key, lit as on the typing screen, on a relief. To change it, edit
`_build/icon.mjs`, run it, and generate the sizes with `npx tauri icon design/icon.svg -o <temp folder>`.
Copy only the five files listed in `src-tauri/tauri.conf.json` and `icon.png` into `src-tauri/icons/`:
the command also creates Android, iOS and Windows Store sizes, which this project does not use.

The app imports `tokens.css` directly. `src/styles/relief.css` is a copy of the parts of
`screens/assets/screens.css` it uses so far, and `src/styles/app.css` holds what the mockups did not draw
when the app was built, such as the session setup on the home screen. "Starting a session" below
replaces that setup.

## Principles

1. **The text comes first.** The typing screen has no navigation. The current character, errors and
   the next key are readable at a glance, everything else is quiet.
2. **State is never colour alone.** Each character state differs in shape as well as colour, so the
   screen survives colour blindness and a greyscale display. See "Typed text" below.
3. **The accent means "now".** It marks the primary action, the current selection and the current
   character. One filled primary button per screen.
4. **Rewards stay out of the way.** They appear beside the keyboard, or in the reserved band at the
   bottom edge while the keyboard is off, and never over the text. They take no focus, shift no
   layout and fade on their own.
5. **Data explains itself.** Focus, tips and the brain panel state the figure behind them. An
   inconclusive A/B result is shown as inconclusive.
6. **Every policy has a switch.** Clean mode removes XP, levels, quests, events and achievements from
   every screen and leaves a complete app.
7. **Failure is calm and offline.** Error states say what is safe and what to do. The journal is
   always the way back.

## Using the mockups

Each screen has a Mockup control at the bottom right: theme, data state, clean mode, colour vision
simulation, on typing screens the live figures, keyboard mode and reward demos, and on pages with
several states a State list. Theme offers Light, Dark and System, and starts on System, as the app does.
The same options work as URL parameters: `?theme=dark|light|system`, `?data=loading|empty|error`,
`?gam=off`, `?figures=off`, `?kbd=error|off`, `?vision=...`, `?variant=...`.

Typing screens accept real keystrokes: errors, Backspace, Enter with auto-indent on the code screen,
Esc to pause. This is a demo in `review.js`, not a design for the input path. All figures are samples,
and lyrics, subtitles and videos are original placeholders.

Screens are checked at 1366×768 and 1920×1080. Above 1366 the content is capped and centred, and the
typing text and keys grow. The screens of the first app builds are also checked at the app's window,
1100×720, and its minimum, 720×480. See "Window sizes" below.

## Tokens

Components use role names and never raw values, so a theme is only a set of role values. The source
is OKLCH, with sRGB hex alongside in `tokens.json`.

| Group            | Names                                                                                                         |
| ---------------- | ------------------------------------------------------------------------------------------------------------- |
| Surfaces and ink | `--color-paper`, `-paper-2`, `-paper-3`, `-ink`, `-ink-2`, `-muted`, `-rule`, `-rule-2`, `-field-edge`        |
| Meaning          | `--color-accent`, `-accent-soft`, `-signal`, `-focus`, `-target`, `-target-soft`                              |
| Typed text       | `--color-upcoming`, `-done`, `-caret-bg`, `-error-bg`, `-error-ink`, `-error-mark`                            |
| Data             | `--color-heat-0` to `-5`, `--color-chart-1`, `-chart-2`, `--color-contour`                                    |
| Type             | `--font-ui`, `-display`, `-typing`, `-code`; `--text-xs` to `-4xl`; `--weight-regular`, `-medium`, `-display` |
| Space and shape  | `--space-3xs` to `-3xl`; `--radius-glyph`, `-ui`, `-key`, `-pill`; `--control-sm`, `-md`, `-hit`              |
| Motion           | `--dur-micro`, `-short`, `-long`, `-ripple`, `-reward`; `--ease-out`, `-settle`                               |
| Typing screen    | `--typing-size`, `--typing-column`, `--typing-lines`, `--reward-band`, `--bar-h`                              |

Fonts are Golos Text and JetBrains Mono, both under the SIL Open Font License, both with Cyrillic
including Ukrainian. The app bundles them as woff2 to stay offline, and the mockups use the same files,
Latin subset only.

Chart colours pass the dataviz palette validator in both themes. Heat is one hue from light to dark,
and a number stays on each key, so the map never relies on colour alone.

## Components and states

`screens/components.html` draws every component below in the states normal, hover, focus, error and
disabled, in both themes.

| Group      | Components                                                                           |
| ---------- | ------------------------------------------------------------------------------------ |
| Controls   | Button (primary, secondary, quiet), input, select, switch, segmented control         |
| Navigation | Top bar item, tab, link                                                              |
| Product    | Key, quest row, achievement row, session row, meter, heat cell, reward               |
| Sessions   | Message in the slot, mode on the rail, quick session row, library row, theme picture |

Rules shared by all states:

- **Hover** changes the surface. A switch gets a soft ring instead.
- **Focus** is a 2px ring from `--color-focus`, shown instantly on `:focus-visible`.
- **Error** uses `--color-signal`, a heavier edge and a "!" glyph with a message, not red.
- **Disabled** lowers contrast and removes hover. Explanatory text stays readable.

### Typed text

| State                     | Shape                                                            | Why it reads without colour           |
| ------------------------- | ---------------------------------------------------------------- | ------------------------------------- |
| Upcoming                  | Muted ink                                                        | Lighter than done text                |
| Target                    | Thick underline under the transition                             | Line under the letters                |
| Current                   | Filled block in the accent                                       | Filled block                          |
| Done                      | Full ink                                                         | Darker than upcoming text             |
| Error                     | Inverted block, heavy lower mark, typed character in a tag above | Inverted, with the wrong letter shown |
| Fixed                     | Dotted underline                                                 | Stays visible after the correction    |
| Skipped, continuous video | Struck through                                                   | Line through the letters              |

Rules that keep the typing screen fast at any text length:

- A state never changes the width or height of a character, so no change of weight or size.
- Line breaks are measured once and stored, including the height of the window for a short text.
- A press repaints at most two characters and moves the text with `transform`.
- Effects only touch those two characters. Nothing animates all the text.
- Messages and rewards live in reserved space or outside the layout, so the text never shifts.

### On-screen keyboard

There is one component, `keyboard()` in `_build/lib.mjs`, with the finger hint `hand()` beside it. It
takes these variants:

- **Typing:** next key filled in the accent, target keys underlined, the finger named in words.
- **Locked:** keys that have not opened yet.
- **Heat:** the statistics screen, one attribute `data-h` per key, switched by metric and by view.
- **Ghost:** quiet keys over the relief on the home and onboarding screens.
- **Key feedback:** pressed `is-down`, wrong press `is-wrong`.

The policy has three modes: on, only on error, and off. The band keeps its space in "only on error",
so the text does not jump. When the keyboard is off, the text takes the space and rewards move to the
bottom edge of the window.

### Data states

Every region that reads data has four states: full, loading (skeleton), empty (what to do next) and
error (what is safe, and a way back). The markup comes from `region()` in `_build/lib.mjs`.

### Rewards

| Reward     | Position                             | Motion                                              |
| ---------- | ------------------------------------ | --------------------------------------------------- |
| XP         | Left of the keyboard                 | Fades in and out, 2.6 s                             |
| Quest done | Right of the keyboard                | Same                                                |
| Level up   | Right of the keyboard, in the accent | Same, plus a contour ripple through the band, 0.9 s |

With `prefers-reduced-motion` the rewards appear without movement and the ripple does not run. If
several arrive together, they stack in their column.

## Starting a session

`screens/session-setup.html` is a separate screen, and Home keeps the last setup one action away.
This is how it stays one action as modes are added:

- **Home has one primary, and it starts at once.** It repeats the last setup: Words, 25 words, top
  1,000 on first launch, and Adaptive once that mode exists. It takes focus on arrival, so Enter starts.
  When that setup cannot start again, the primary opens the setup instead. See "When the last setup
  cannot repeat".
- **Other sessions** on Home: at most three recently used modes, each with its remembered setup, a
  secondary Start and a Change link. All modes opens the setup screen.
- **Setup screen:** a rail of modes on the left and one panel. The rail holds nine modes at 720×480
  with no scrolling and no collapsing. A mode with nothing to set shows a line of text and Start.
- **One primary, in a sticky foot,** beside a one-line summary of what will start. When nothing can
  start, the primary is disabled and the summary says what is missing.

Library rows use `.lib`: a radio, the title in two lines at most with the full name on hover, the
size, how much is read, and Delete.

| State           | What happens                                                                    |
| --------------- | ------------------------------------------------------------------------------- |
| Empty           | Says what to add. Start is disabled and says why                                |
| Importing       | A row with a moving bar, and the rest of the library stays usable               |
| Unreadable      | The error stays in the row: nothing was added, the library is unchanged         |
| Nothing to type | Same row, and names the layout. Characters left out are counted in a note       |
| Finished        | A Finished tag, and the primary becomes Start again, so the restart is explicit |
| Very long title | Two lines in the row, one line with an ellipsis in the foot and the panel       |
| Delete          | Confirmed in the row, focus on Keep                                             |

Delete confirms instead of offering undo. Undo needs a delayed deletion, and closing the app during
the delay would leave the file either way without the person knowing which.

## When the last setup cannot repeat

`home-now?variant=...` draws each case. The rule comes from ADR-0007: Home never starts a session it
cannot start, and opens the setup of that mode instead.

- **The same place, one primary.** The sheet keeps its shape. The heading says the situation, one line
  says why, and the primary names what happens next instead of "Start session". It still takes focus,
  so Enter goes to the setup.
- **One action to type stays.** Other sessions keep the modes that can start at once, and Words always
  can.
- **Change setup goes away,** because the primary now does that job.

| Variant        | Heading                          | Why                                                            | Primary       | Opens           |
| -------------- | -------------------------------- | -------------------------------------------------------------- | ------------- | --------------- |
| `paste`        | Paste a new text                 | A pasted text is not kept, so the last one cannot start again. | Paste a text  | `texts-paste`   |
| `deleted`      | Choose a new text                | The file from your last session was deleted.                   | Choose a text | `file-list`     |
| `device`       | Your file is on another computer | Files stay on the computer they were added to.                 | Choose a text | `file-list`     |
| `device-empty` | Your file is on another computer | The same, and this computer has no files yet.                  | Add a file    | `file-empty`    |
| `finished`     | You finished Walden              | Choose what to read next, or read it again.                    | Choose a text | `file-finished` |

A row in Other sessions can hit the same case, shown in `row`. It keeps its place, says why in its text,
and offers the setup where Start was: `Paste` beside "A pasted text is not kept", or `Choose` beside
"The file is not on this computer". `home-stats?variant=paste` shows the same words over the map.

What the wording rests on:

- **A deleted file has no name.** `session_started` keeps the file's id, a random UUID, and the title
  lives only in the local library. So a deleted file or one on another computer cannot be named, and a
  finished one can. Keeping titles in the journal would send them through sync, so the copy goes without.
- **Deleted and elsewhere are told apart by the journal folder.** If the last session is in another
  device's folder and its id is not in the library here, the file is on another computer. If it is in
  this device's folder, it was deleted.
- **In the setup the most recently read file is selected,** so the next Enter there starts reading.
- **Loading, empty and error** show the default setup, as Home already does in those states. Only a
  readable setup can be one that cannot repeat.

Adaptive always can repeat, because the brain picks the text, so `home` only needs the row case.

## First launch

`onboarding-theme` is the only step until stage 3. SPEC, "Первый запуск", lists the steps to come.

- **Three cards in the order of Settings:** Light, Dark, System. System is selected and has the focus,
  so Enter accepts it, and the arrow keys move between the cards.
- **A choice applies at once** to the whole window, and is saved by Continue. Closing the window before
  that keeps the default and asks again next time.
- **Each picture shows the theme it names,** whatever the window is showing, through its own
  `data-theme`. System shows both, and its line says what Windows is set to now.
- **No step counter** while there is one step. When the test arrives, this step comes first in the list.
- **If the choice cannot be saved** (`?variant=save-error`), the theme stays for this launch, the step
  comes back next time, and Continue still works, because a look is no reason to stop anyone.

The step loads no data, so it has no loading, empty or error state of its own beyond that one.

## Typing without the keyboard

Until the keyboard arrives this is the main screen: `plain-words`, `plain-time`, `plain-text`. It is
the same screen with `data-kbd="off"`, so it takes the keyboard back without another layout.

- **One column,** `--typing-column` wide. The panel, the text and the message slot form one block a
  little above the middle, because reading sits above the centre of a screen.
- **Four lines,** `--typing-lines`: one past, the current line second, two ahead. Three lines left too
  little ahead with no keyboard to look at, and five pushed the block out of a 720×480 window. A
  shorter text gets a shorter window, set once.
- **Empty space stays empty.** Nothing decorative fills it, so the text keeps the attention.
- **The panel sits directly on the text,** with a hairline under it for progress. The hairline uses
  `transform` and is written by the timer that writes the figures, never by a press. It moves in
  steps with no transition: a glide kept frames busy for the whole session (ADR-0004).
- **Reward band.** The last row is never shorter than `--reward-band`, so a reward has room at every
  window size. XP sits on the left and quests on the right. In a short window, a second reward on the same side waits for the first.
- **By time:** `00:41 left` in the code font, the hairline empties, the last ten seconds get a soft
  block with no change of size, and the slot says "The clock starts with your first key." until then.
- **Policies in force:** a tag in the panel, such as "Backspace off", only when the policy changes what
  a key does. Live figures gets no tag, because an empty panel explains itself.
- **Live figures off** (`?figures=off`, and the Live figures row in Settings). The panel keeps the mode,
  its detail and "Esc to pause". WPM, accuracy, elapsed time and the Code recovery figure go, and their
  timer does not start. The hairline stays as a still rule, because the same timer writes it, so nothing
  moves. **By time** keeps `00:41 left`, the emptying hairline and the soft last ten seconds, because a
  limit is not a metric. The summary keeps every figure, and the text does not shift between on and off.

### Zen

`typing-zen` has no sample text and no figures. The panel holds only the mode and "Esc to pause", at
the top of the window. The writing line stays in one place, a little above the middle, and older lines
rise and fade through a static mask, which never animates. Rewards keep their band below.

The caret is its own element, `.zen__caret`, a 3px bar in the accent, as tall as the font, because Zen
has no next character to light up. It does not blink while typing, blinks softly after a pause, and
stays still with `prefers-reduced-motion`.

### Messages while typing

`typing-messages` shows all of them. There is one slot under the text, always one line tall. A message
replaces the source line while it lasts, so nothing moves, and it never takes focus.

| Message                                                                             | Level  | Appears                       | Clears                         |
| ----------------------------------------------------------------------------------- | ------ | ----------------------------- | ------------------------------ |
| Stopped on an error. Press the right key to go on.                                  | Action | 600 ms after a wrong key      | The right key                  |
| Switch the keyboard to English. This press was not counted.                         | Action | A key off the layout          | The next counted press         |
| Backspace is off in this session. Keep going.                                       | Action | Backspace while it is blocked | The next counted press, or 3 s |
| Caps Lock is on.                                                                    | Action | Caps Lock turned on           | Caps Lock turned off           |
| Saving is delayed. Your typing is kept and is written as soon as the disk responds. | Wait   | The disk falls behind         | The disk catches up            |

- **Two levels, two shapes:** action has a filled "!", wait has an outlined "…". Colour is not needed.
- **One at a time,** in the order of the table. A lower message comes back when a higher one clears.
  Saving is last because it asks for nothing, while the others explain why a press did nothing.
- **The stop itself is immediate:** the character shows the error and the key you pressed. The words
  wait 600 ms, so a quick correction does not flash a message.
- **Focus loss opens the same dialog as Esc,** with one line that says why the clock stopped.
- **Keys in flight.** The Resume button, and the primary on a summary reached by a running clock, take
  focus only after a short delay. Someone typing at speed would otherwise press them with Space.
- The text is written only when it changes, so a held key costs nothing.

## Session summary

`summary-plain` has only what a Words, Texts or Zen session really has. WPM and accuracy lead, then CPM,
rhythm evenness and time in one row. There is no XP on it.

| Variant           | What differs                                                                        |
| ----------------- | ----------------------------------------------------------------------------------- |
| By count, by time | The line under the title names the setup                                            |
| Text              | The line names the source. From a file, a meter shows the reading progress          |
| Zen               | No accuracy, and the note says why. WPM and time lead                               |
| Ended early       | The title says so, the line says where it stopped                                   |
| Ended very early  | A dash where there were too few presses to measure, and the note says what it means |

`session-summary.html` stays the summary for an adaptive session.

## Window sizes

Every state of the screens above was loaded from disk at each size and checked for content past the
window edge and for a Start button out of view. The main states were also read by eye.

| Size      | Themes      | Result                                                                                                 |
| --------- | ----------- | ------------------------------------------------------------------------------------------------------ |
| 1920×1080 | Light       | Fits, capped and centred                                                                               |
| 1366×768  | Light       | Fits                                                                                                   |
| 1100×720  | Light, dark | Fits, only long lists scroll                                                                           |
| 720×480   | Light       | Works: setup rows stack, the page scrolls, Start stays in the sticky foot, typing shows all four lines |

The first-launch step, every case of the last setup that cannot repeat and live figures off were checked
at all four sizes in both themes. At 720×480 the long title on Home takes one line instead of two.

The window sizes in `tauri.conf.json` can stay for these screens. The keyboard does not fit a 720 wide
window at its current size, so the minimum needs another look when it returns.

## Tray and notification

`screens/tray.html` shows content only. In the app both are native Windows surfaces, so Relief styling
does not reach them:

- The Tauri 2 tray menu supports text, check items, separators, disabled items and text updates.
- The Tauri notification plugin documents action buttons for mobile only, so the Windows reminder is
  a title and a body.
- Whether the plugin reports a click on desktop is unconfirmed. Check this at stage 6, because SPEC
  wants a click to open a short session. A small custom webview window is the fallback.
